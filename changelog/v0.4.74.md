# v0.4.74

## Performance: select-all rows inherit their navigation getters from a per-schema prototype

`table.where(...)`, `table.with(...)` and a filter-join taken straight off the table all bootstrap
the query with a **select-all row**: the object a chained `.select(...)` receives. It carries every
column as an own enumerable property (the selection walkers downstream read those with
`Object.keys` / `Object.entries`) plus every navigation as a **non-enumerable** getter, so
`.select(u => ({ posts: u.posts!.where(...) }))` resolves while the default projection stays
columns-only.

That row was rebuilt from scratch on **every query build**, and the navigation half was the
expensive half: one `Object.defineProperty` call per navigation property, per build. On a wide
entity that dominates the wrapper — a 45-column / 47-navigation table (a gopass-eshop `order`)
spent ~5 µs of every build defining 47 getters that are a pure function of the schema, only for
the user's `.select(...)` to project four columns.

The getters now live on ONE prototype per schema (`WeakMap`-keyed on the schema object, so a
prototype is dropped with its schema); a row is `Object.create(prototype)` plus a non-enumerable
symbol slot holding the mock row the getters read through. Measured on a stub driver, build cost
of `where(...).select(4 columns)`:

| entity shape | before | after | |
| --- | --- | --- | --- |
| 6 columns / 3 navigations | 2.5 µs | **1.8 µs** | −28 % |
| 45 columns / 47 navigations | 10.1 µs | **4.5 µs** | −55 % |
| 78 columns / 41 navigations | 12.3 µs | **6.8 µs** | −45 % |

**Nothing observable moves.** Only non-enumerable properties were relocated, and non-enumerable
properties never appear in `Object.keys` / `Object.entries` / spread / `for...in` — every
enumeration downstream sees exactly the columns it saw before. `row.constructor` still resolves
to `Object` through the chain, which is what the query builder's `isPlainObject` tests, and the
internal slot is non-enumerable so it cannot leak into a spread. The only difference is
own-property introspection of a navigation name (`hasOwnProperty(relName)`,
`getOwnPropertyNames`), which nothing in the library performs on a selection.

This is unconditional — no switch, no opt-in — because the getters are pure functions of the
schema, exactly like the column metadata cached in 0.4.69. It is independent of
`MockRowCache.setEnabled`, and compounds with it: the mock row the select-all row reads through
is itself prototype-shared when that cache is on.

Guarded by `tests/queries/select-all-row-prototype.test.ts`: the emitted SQL for a `where()` with
no chained select (every column projected), a narrowed chained select, and chained `hasMany` /
`hasOne` navigations; the row's enumeration surface (`Object.keys`, spread, `for...in`,
`hasOwnProperty`, `constructor`); that two `where()` calls on one schema share a prototype; and
that two schemas do not. Full suite: 1,623 tests pass (122 suites).
